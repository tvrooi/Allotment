<objective>
Route the category-row selectors of the Review, payee, rules and recurring specs through
`categoryOption`, while CategoryPicker is still hand-rolled, and measure every such selector in
those seven specs (WAVG-02, WAVG-03; ROADMAP success criterion 4).

Purpose: CategoryPicker's rows become listbox options in plan 02-18, so every spec that finds a row
by the button role would break. Routing them through one helper first, on the unchanged picker,
keeps each plan green and makes plan 02-18's role change one line. A missed positive selector would
fail loudly in 02-18, but a missed negative one (`toHaveCount(0)` on a category name,
`review.spec.ts:56`) would pass forever against a role that no longer exists, so this plan
finds them by reading as well as by the role experiment.

Scope (third plan revision, checker round 3): the 20 candidate specs are split by owner into three
plans, and each plan measures, moves and proves only its own: this plan the 7 below, plan 02-20
the import, freshness, polish, recovery and phone specs (6), plan 02-18 the last 7. The round-2
version of this plan held 13 specs and measured all 20, so with the two files the role experiment
edits its real scope was 15 and more. Its `files_modified` now lists everything it touches: 7
spec files it commits, and `CategoryPicker.tsx` and `e2e/tests/fixtures.ts`, which the role
experiment edits and reverts and which are never committed here. 9 files. No source file is
committed.

This plan has no tracer task: it adds no path through the app. Plan 02-10's tracer proved the
helper and the shared list; this plan moves existing selectors onto that helper.
Output: the 7 spec files with their category rows on `categoryOption`, and their measured selector
list in the SUMMARY.
</objective>
