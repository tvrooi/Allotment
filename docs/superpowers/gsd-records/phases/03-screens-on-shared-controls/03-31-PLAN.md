<objective>
Remove the server route that only the old Mark reviewed button used (checker I1, owner-requested
UAT change G-03-2, 21 November 2026). 03-28 removed that button and its client request; marking a
list reviewed now goes through the bulk route the selection menu uses. CLAUDE.md: "A change removes
what it replaces: unused exports, routes...". Planning checked the other callers: routes/mcp.ts has
no tool on it, server/src/browser/app.ts only mounts the shared router, assistantPolicy.ts and the
read-only token allowlist (accessTokens.ts lists the GET /review page data, a different route)
never allowed it, and no doc other than PHASE-9-DEVELOPMENT-PHASE.md names it.

Why removal rather than keeping it for compatibility: the web client, the desktop app's remote
pages and the HA app all load the client the server serves, so no shipped client still calls it
after this release; the service worker keeps only the app shell for offline opening, when no
request reaches the server anyway.

Purpose: one path for marking reviewed, no dead route.
Output: the route, its schemas and its two service functions removed; the old route test ported to
the bulk route; the doc updated.

No tracer task: this plan adds no path; it removes one and proves the remaining path keeps its
guarantees.
</objective>
