<objective>
Close the first half of UAT gap G-03-2 (major, test 2). The owner, 21 November 2026: "I should be
able to select individual transactions in addition. I do not want an edit modal as is currently
present, I should be able to just right click after selecting and edit them with the same options
that way".

This plan builds the hand-picked selection and its right-click menu with Review and Share. 03-30
adds the Edit dialog's other options to the menu (the ContextMenu prompt item, category, payee,
notes, tags, reports) and the paused rule; 03-28 then routes Select all and Delete through the same
selection and removes the Edit N dialog. (Split from one larger plan to stay inside the context
budget, checker W5.)

Owner-approved during planning, 21 November 2026 (decision B; distinct from the owner's UAT
request above, and recorded as such in the 03-29 PR body):
- Pick to share is renamed Select and becomes the one register selection. The register already
  had one row selection, Pick to share (checkboxes for sharing, right-click on a picked row shares
  them all). It becomes the general selection: every row is selectable, the button is `Select`,
  the bar is `Selected transactions`, and sharing is a menu and bar action on the selected rows
  sharing accepts. A second mechanism beside it would be the duplicated logic CLAUDE.md ranks P1.
- The Pick all shown button is removed: Select all N above the list covers it (03-28).
- Edits apply at once from the menu, with Undo in the toast, instead of the dialog's preview and
  confirm. The guard against acting on a list by accident stays: an explicit selection first,
  the server's expected-count check, the register's params intersected with the ids, and Undo.
  Delete keeps its typed confirmation (03-28).

Facts from planning (verified against the tree at 734a8d82):
- The server already takes hand-picked rows: `POST /transactions/bulk` and `/transactions/bulk-delete`
  accept `ids` and `excludeIds` beside the selection (`bulkTargetSchema`, routes/transactions.ts;
  `targetRows` in services/transactionEdits.ts, tested in transactionEdits.test.ts). The client's
  `BulkTarget` in api/transactions.ts has `ids` but not `excludeIds`. No server change is needed.
- `bulkEdit` compares `expectedCount` with every matched row (skipped fields included), so the
  expected count is the number of selected rows. Reconciled rows take category, payee and notes
  edits; transfers skip category and payee, split parents skip category, household-linked rows
  skip all three (`ledgerBlock`). The 409 text is "The selection now has N transactions, not M.
  Check it and try again."
- `useBulkEdit` takes `{ params, changes, expectedCount, message? }` with
  `message?: (changed: number) => string`; CategoryFollowupToast also calls it.
- TransactionTable keeps `picked: Set<string> | null`, `togglePick`, `withPick` (checkbox column
  on rows and cards, names `Pick {payee} {amount}`, disabled unless `shareable`), the `Pick to
  share` button (only with households) and the `Picked payments` region; `MenuTarget` wraps each
  row and card and calls `setMenu({ tx, at })`; `TransactionContextMenu` gets `pickedIds` and
  shares all picked rows when one of them is right-clicked.
- ContextMenu supports one sub-menu level, flyouts on desktop and in-place with Back on phones,
  Tab closes it, and it returns focus on close.
- Desktop row click opens details (#243). On a Mac, Ctrl+click fires contextmenu, not click.
