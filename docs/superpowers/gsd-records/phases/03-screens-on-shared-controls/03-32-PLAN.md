<objective>
Close UAT gap G-03-3 (cosmetic, test 49). The owner, 22 November 2026: "Pass, but the spacing of
the date text within the input field appears incorrect." Screenshot Allotment.png (iPhone
Safari): "26 Nov 2026" sits at the top of the Date field while Amount and Payee are centred; the
field's size and the iOS date wheel are right (G-03-1's fit fix holds).

Cause (diagnosed, 03-UAT.md): NativePicker's phone `<input type="date">` takes `block` from
`fieldBase`. iOS Safari's own style for a date input is an inline flex box that centres its value
box (`::-webkit-date-and-time-value`); `block` replaces that, so the value box stacks at the top of
the 44 px field. A text input centres its line whatever its display, which is why Amount looks
right. Tailwind's preflight already gives that value box `min-height: 1lh` and
`text-align: inherit` (seen in the built CSS at planning time).

Fix, in NativePicker only (D-04), iOS only by construction: give the value box no vertical margin
and a line as tall as the field's inside (44 px less two 1 px borders = 42 px), so its text sits in
the middle. Chromium and desktop WebKit never create that pseudo-element, so they do not change.
This is a layout fix, not a behaviour change (D-15).

Purpose: WAVG-05 (Add transaction) and WAVG-06 (the G3 date fields share NativePicker) read
cleanly at 390 px on the iPhone.
Output: two utility classes on the NativePicker input, a failing-first unit test, a built-CSS
check, on branch `fix/uat-03-date-centre` (03-34 merges it into the round's PR).

The code work happens in its own worktree from origin/redesign, because the main checkout's local
`redesign` is behind origin/redesign (it lacks the squash merges of #280 and #281) and carries
unpushed .planning commits. Read every source file from the worktree, never from the checkout.
Plan 03-33 runs in parallel on its own worktree; this plan runs no browser test, so the fixed e2e
ports never clash (the browser runs for this change are 03-34's).
