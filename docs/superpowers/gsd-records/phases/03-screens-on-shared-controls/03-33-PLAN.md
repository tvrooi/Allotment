<objective>
Close UAT gap G-03-4 (minor, test 51). The owner, 22 November 2026, on up.179: "instead of adding
the checkbox to the left and moving the content in the row to the right; a selected row should
change colour to indicate it has been selected so the content does not move when selected. No
checkbox should show up. Otherwise, the right click options pass." Asked directly the same day
whether the list may move down when selecting starts, the owner decided: "Don't move the list".

Target: while selecting, a click (desktop) or tap (phone) on a row toggles it, a selected row
changes colour, no checkbox shows, and no row moves at all, sideways or down, at 1280 px or
390 px. The right-click menu and every action in it already passed UAT and stay exactly as they
are.

Cause (diagnosed, 03-UAT.md, plus the owner's decision): `withSelect` in TransactionTable.tsx wraps
every row and card in a flex row with a shared Checkbox cell while selecting, which pushes the
content right; a plain desktop click still opens details; the row has no selected colour of its
own (bg-brand-50 with `border-l-2` is the open-in-details highlight); and the selection bar is a
new block between the toolbar and the list, so the whole list moves down by its height when
selecting starts.

Planner's choices within the owner's request (recorded for the PR in 03-34):
- The row itself is the checkbox for assistive technology while selecting (`role="checkbox"`,
  `aria-checked`, named `Select {payee} {amount}`, exactly the old box's name), so screen-reader
  users hear the same control and specs keep their locators; nothing of it is visible. A
  checkbox's children are presentational, so while selecting the row's inline controls are drawn
  as plain elements of the same size (no nested control) and work again after Done. The listbox,
  grid or `aria-pressed` patterns the diagnosis also allowed were weighed: listbox options and
  toggle buttons have the same presentational-children rule, and a grid needs arrow-key cell
  navigation across the whole register, a larger change than the request.
- A plain click (or tap) selects instead of opening details while selecting; outside select mode
  it opens details as before.
- The selected fill is `bg-brand-100` plus a 3 px inset `--color-brand-600` bar
  (`shadow-[inset_3px_0_0_var(--color-brand-600)]`): brand-100 is the strongest brand tint that
  keeps every row text colour at 4.5:1 in both themes (brand-200 drops tertiary text to 4.23 in
  light), but against white it is only 1.17:1, so the bar carries the state at 3:1 or more
  (WCAG 1.4.11). An inset shadow takes no space, so nothing moves. One constant, used by row and
  card.
- Enter and Space both toggle a focused row while selecting (the phone card is a native button,
  which does the same).
- "Don't move the list": the bar overlays the toolbar's box instead of being a block above the
  list. The toolbar stays in the layout with content that no longer depends on selection (the
  same height by construction), invisible and inert while selecting, so nothing below it can move.
  Swapping the toolbar out for a bar of equal height was weighed: the toolbar's height varies with
  the page (an account page adds Import CSV and Add Transaction) and the summary, so a second box
  cannot match it exactly, while an overlay inherits it. While selecting, the toolbar's Export,
  Import CSV and Add Transaction are therefore under the bar; Done brings them back. The bar gains
  Select all N (the toolbar's own is under it), and focus moves to the bar when selecting starts
  from the toolbar, so keyboard users are not dropped to the page's start.
- On a phone the bar is laid out to fit the shortest toolbar (the all-transactions register,
  about 158 px computed from its classes at planning): its hint is one short line, "Tap transactions to select them.",
  above two rows of 44 px controls (the count, More actions, Select all and Done; then Share and
  Clear). The longer hint wrapped to two lines and, with the household Share button, made the bar
  taller than that toolbar.
