# Form controls audit

Wave G0 (#267, WAVG-01): every field and selector the owner reads before any shared control is
built (D-10). Taken on 17 November 2026 at commit `6520896` (`git log -1 --format=%h -- client/src`, the last
commit that changed `client/src`). Counts are of JSX elements read from the TypeScript syntax tree
in the 310 non-test `.tsx` files under `client/src`, so a tag name in a comment or a string is not
counted. Accessible names are quoted exactly as written in source; an expression is shown as code.

This audit covers the whole of `client/src`: every raw `<select>`, `<textarea>` and `<input>`, and
every use of the sixteen control components. Plan 02-01 wrote the rows for the everyday money areas
(G2): `components/{transactions,accounts,budget,payees,rules,recurring,ui,layout}/` and their pages
(`Transactions`, `Accounts`, `AccountTransactions`, `AccountConnections`, `ReconcilePage`, `Budget`,
`BudgetCategories`, `AnnualBudget`, `CategoryDetail`, `Payees`, `PayeeDetail`, `Rules`,
`RecurringTransactions`). Plan 02-02 added the remaining areas (G3 and G4), the sections after
"Not a control" and the screenshots.

**Recount.** The whole table is taken at one commit. A recount replaces every table and the commit
above together, never single rows. The places the tables must cover are what these print (run from
the checkout root):

```sh
grep -rnoE '<(select|textarea|input)\b' client/src --include='*.tsx' | grep -v '\.test\.tsx:' | cut -d: -f1,2 | sort -u
grep -rnoE '<(Input|Select|CurrencyInput|Switch|DatePicker|MonthRangePicker|SegmentedControl|Slider|CategoryPicker|PayeeCombobox|CategorySelect|CategorySelectButton|MerchantSelect|OptionPicker|IconPickerPopover|DefaultCategoryButton)\b' client/src --include='*.tsx' | grep -v '\.test\.tsx:' | cut -d: -f1,2 | sort -u
```

The rows themselves come from a throwaway script, kept out of the repository, that walks the same
files with the TypeScript 6 compiler API in `lint/node_modules/typescript` (the client's TypeScript 7
has no JavaScript API) and reads, for each element, its opening line, `type`, state props, name
props, wrapping or `htmlFor` label and `onChange` handler. Its e2e column matches each control's
accessible name against `e2e/tests/**/*.ts` selectors of the control's role (`getByRole`) or any
`getByLabel`, `getByPlaceholder` or `getByTitle`. A name built from an expression is matched by its
static prefix and marked so; "(+N)" is N more lines in the same spec. What a control chooses and what
it becomes were read from the code around it.

## Every control

Columns: **Where** is the file and the line of the element's opening `<`. **Today** is the element or
component. **States** lists which of disabled, invalid, read-only, Safe mode and paused saving
(`useCanSave`) the control itself handles, as the code does it today. **Name** is the accessible name
and how it gets it. **Becomes** is the shared control under D-05 and D-06: Select for a fixed list,
Combobox for a list the user grows, CategoryPicker for categories, PayeeCombobox for payees, or
"stays native" with the reason. **Moves in** is the phase and Wave G step that moves it (Phase 3 G2
everyday money, G3 planning, reports, files and import; Phase 4 G4 settings, banks and the shelved
pages, which get a like-for-like swap under D-09).

Rows are in file path order, then line order, inside each area. Two controls on one line are two
rows, and a component used N times has N rows.
